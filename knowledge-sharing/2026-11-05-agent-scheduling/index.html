Part 01 · 定义之争
Agent 到底是什么？一条自治程度谱系
市面定义很混乱，但按"自治程度"从左到右排列，一切就清晰了
L0 · 被动应答
Chatbot
你问一句
它答一句
L1 · 单点能力
工具调用
能调计算器/搜索
但每步靠人触发
L2 · 固定流程
工作流编排
人预设流程
模型在节点执行
L3 · 目标自治
自主智能体
自拆解 · 自选工具
自评估 · 自重试
← 真正的 Agent
Agent= 大模型 LLM+ 规划 Planning+ 记忆 Memory+ 工具 Tools
关键事实：公式四组件中，只有大模型是端到端训练的神经网络，其余三个（规划/记忆/工具）全部是工程系统。
这个细节正是后面所有争论的根源 —— 端到端 vs 模块化，争的就是这四个组件各自该长多大。

Part 03 · 范式一
ReAct：思考 → 行动 → 观察 循环
LOOP ⟳
💭
思考 Thought
"我要先查一下相关资料"
⚡
行动 Action
生成结构化调用
search("...")
👁️
观察 Observation
工具结果
喂回上下文

✓ 三大优点

▸结构极简：一个提示词模板就能跑起来
▸每步留痕：有完整推理链，出问题易排查
▸灵活探索：适合开放式小任务（查资料、写初稿）

✗ 三大短板

▸走一步看一步，缺全局规划，长任务易迷失
▸每圈完整调用一次大模型，20圈=20次推理成本
▸中间某步出错，错误沿上下文持续累积

Part 04 · 范式二
Planner–Executor：先画地图，再行军
INPUT
🎯 复杂目标
"生成一份行业分析报告"
强模型
🗺️ Planner 规划器
一次输出完整计划：检索 → 分析 → 生成 → 校验
小模型/纯代码
⚙️ Executor 执行器
逐步执行计划，便宜、快、可并行
OUTPUT
📦 结果 + 可审计的计划文档
计划偏了？触发重规划 Re-plan
🌐

全局最优

规划器看过全貌，不走一步看一步，不易迷失

💰

成本可控

贵的推理只发生在规划环节，重活交给便宜执行器

📄

可审计可回滚

计划本身是一份文档，工程上好做灰度与回滚

代价：整个系统建立在规划器这张"地图"上——任务复杂到规划器自己都拆不清楚，全盘皆输。业界常用做法：最强模型做规划 + 便宜模型做执行。

Part 05 · 范式三
多智能体协作：分工、辩论与纠错
🧑‍✈️
规划智能体
Orchestrator · 分派任务
🔬
执行体 A
检索 / 调研
💻
执行体 B
编码 / 计算
✍️
执行体 C
写作 / 生成
🛡️
校验智能体
挑错 · 验证结果
⚡ A↔C 互相辩论攻击漏洞
📡

通信开销巨大

智能体之间传递的信息爆炸式增长，token 成本数倍上升

🦠

错误会传染

一个智能体的幻觉，可能被另一个当成事实继续放大

📉

收益常被高估

很多场景下，一个足够强的单智能体 + 好工具，效果反而更好

实践者教训（事实层面）："多智能体"不是银弹。上多智能体的正当理由只有两个——任务真的需要并行，或者需要独立视角互相纠错。

Part 06 · 核心争论
端到端 还是 模块化？
端到端派
让一个大模型直接从目标生成最终结果——检索、排序、规划全部内化在模型参数与推理过程里，不再显式调用外部算法。
类比历史：GPT 当年吞并了 NLP 的各个子任务
（翻译、摘要、分类曾是独立模型）
VS
模块化派
承认大模型只负责思考与决策，具体能力交给专业算法：检索交给向量库、推荐交给排序模型、求解交给运筹引擎。
模型是调度员，不是全能选手
—— 各司其职，组合成系统
有意思的现象：学术界的选择偏端到端——追求能力上限与通用性
工业界的选择偏模块化——追求可靠、可控、可负担
两条路线几乎相反，为什么？看下一页的论据

Part 07 · 端到端派的三大论据
"凡是能被数据描述的，终将被模型吞并"
01
📈

Scaling Law 缩放定律

过去五年，模型每放大十倍，就涌现出原本需要专门算法才能实现的能力。数学推理、代码生成——都是先有专门系统，后被模型吞掉。

历史证据：专业翻译模型 → 消失
02
🧠

推理模型的崛起

OpenAI o 系列、DeepSeek-R1 通过强化学习学会长链条思考：原本需要外部规划器才能完成的分解与回溯，现在模型内部就能完成。

直接动摇 Planner 范式的根基
03
🤖

具身智能的信号

机器人领域，感知-规划-控制三段式流水线正在被端到端 VLA 模型（视觉-语言-动作）取代——端到端训练消除了模块之间的信息损失。

VLA: Vision-Language-Action
端到端派的结论：外部算法只是历史阶段的拐杖 —— 能力来自模型
08 / 12
Part 08 · 模块化派的四大论据
"模型负责智能，算法负责正确"
01
✅

可验证性

模型的一百行推理过程无法证明它对；但一次数据库查询、一次最短路径计算，结果是可以证明的。金融、医疗、监管要的恰恰是"可验证"。

02
💰

成本与延迟

端到端意味着每次决策都调用大模型；经典算法调用的成本可能只有它的万分之一。自动驾驶的教训：量产系统依然保留规则与约束层，因为安全必须可解释。

03
🧱

数据的墙

模型学不会训练集里不存在的东西：企业私有逻辑、实时库存与价格——必须通过外部工具实时获取，参数化不了。

04
🌪️

组合爆炸

真实业务是长尾的。你没有预算为每个场景收集训练数据，但你可以为每个场景写一条规则——规则的成本是线性的。

模块化派的结论：智能来自模型，正确来自工程 —— 两者缺一不可

Part 09 · 我的判断
这不是二选一：伪命题与分层
⚠ 以下为个人观点 · 非业界共识 · 标注为推测
🧩

两者回答的是不同维度的问题

端到端回答"能力从哪来"——答案是模型；
模块化回答"系统怎么可靠"——答案是工程。
它们不是对手，而是分层的。

🖥️

个人假设："模型即操作系统"

大模型 = 内核（调度与决策），经典算法 = 系统调用与驱动（稳定执行）。竞争焦点不在路线，而在"内核"与"接口"两层。

🧠 模型即操作系统 —— 类比映射
大模型
↔
操作系统内核（调度决策）
经典算法
↔
系统调用 / 驱动程序
上下文窗口
↔
内存 RAM
外部记忆库
↔
硬盘 Disk
工具 Tools
↔
外设 Peripherals

第一层：内核之争

谁的模型推理更强、更便宜

第二层：接口之争

谁的协议成为事实标准（MCP 等），如同当年的 USB

假设是否成立，需要未来两三年验证 —— 明确标注：这是推测，欢迎用论据反驳

Part 10 · 未来三年推演
顺着"模型即操作系统"往下推
T1

上下文窗口 = 内存

从几十万 token 向千万级演进：整个代码库、整份卷宗直接进工作记忆。检索的意义从"找信息"变成"管理注意力"

已有证据
T2

工具调用成为模型的"母语"

新一代模型在预训练阶段就用工具调用数据训练，调用算法与生成文本一样自然——模型与算法的边界越来越像进程与内核

已有证据
T3

Agent 运行时（Agent OS）出现

专门的 Agent 运行时负责权限管理、沙箱隔离、成本计量、审计日志——就像安卓之于 App

个人推测
T4

价值向上迁移：数据层 + 评价层

当所有人都能调用同样的模型，你的私有数据与验证体系才是别人拿不走的东西——这是对从业者最重要的一条
