02 / 12
MCP 是什么
统一 AI 与工具的连接方式
MCP 是一个开放标准协议，定义大模型如何与外部世界交互。三次统一，一个方向：
硬件接口
USB-C
统一了设备连接，一根线替代所有
网络通信
HTTP
统一了信息传输，全网一个协议
AI × 工具
MCP
统一了模型与工具的连接，碎片化终结
MCP 出现前，每个 AI 应用自定义工具调用格式；出现后，工具与模型有了统一语言
03 / 12
MCP 做什么 · 其一
标准化工具连接，复杂度代数级下降
传统方式
N × M
N 个 AI 应用对接 M 个工具
要写 N×M 套集成代码
复杂度爆炸，维护成本指数增长
MCP 方式
N + M
应用实现一次 Client
工具实现一次 Server
双方协议握手，自由组合
N×M → N+M，这是代数级的复杂度下降

MCP 做什么 · 其二
动态发现与调用，知识在协议层流动
STEP 1
🔍
查询工具
模型运行时通过协议向 Server 查询当前可用工具列表
→
STEP 2
📋
读取 Schema
获取参数类型与返回格式，模型无需预知工具存在
→
STEP 3
⚡
按需调用
工具升级、新增、下线，模型零重训即时感知
模型不需要把工具知识训练进权重 · 知识在协议层流动，不在权重里固化

MCP 协议
三个原语，覆盖全部交互模式
🔧
Tools
模型可调用的函数，带输入输出 schema。每个 Tool 定义清楚参数类型和返回结构。
read_file(path) → string
git_commit(msg) → sha
📚
Resources
模型可读取的数据源。文件、数据库表、API 返回值，统一抽象为可寻址资源。
file:///repo/README.md
postgres://users/table
📝
Prompts
预定义的提示词模板，复用复杂指令。把高质量 Prompt 沉淀为可分享的资产。
code-review-prompt
refactor-template

MCP 为什么重要 · 其一
三大价值，生态统一
01
生态统一
官方 Server 数十个，社区覆盖 GitHub、Notion、Figma、Puppeteer。Anthropic、Cursor、TRAE 均已原生支持
02
工具复用
一个 Server 所有 AI 应用通用。开发者写一次，全网可用，告别重复造轮子
03
可审计性
每次调用都走协议。工具、版本、参数、返回，全链路透明，出错可定位
