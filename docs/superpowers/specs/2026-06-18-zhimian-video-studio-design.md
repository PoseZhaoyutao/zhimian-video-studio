## 2. 递归决策树与 Top-K

### Top-1：准时交付

- 自动生产
  - 单体长脚本：简单但脆弱。
  - 清单驱动：每个阶段有状态，可断点续作。
- 双触发
  - 定时：每天 17:00。
  - 手动：用户说“生成今天的视频”或“调用AI科普视频Skill”。

第一原则：长任务必须可恢复；定时与手动共用日期锁，同日默认只生产一次，明确“重做”才创建新版本。

### Top-2：音画同步

- 时间来源
  - 预估字数：误差会累积。
  - 真实音频：测量每段 WAV 时长后回写时间轴。
- 场景组织
  - 固定帧数：难适配语速。
  - 音频驱动：每段配音对应一个独立场景。

第一原则：音频是真实时间源；Remotion 只消费已测量的逐段时间轴。

### Top-3：品牌一致性

- 视觉资产
  - 每日自由生成：变化大但识别度低。
  - 设计令牌：固定字体、色彩、网格、字幕、转场。
- 栏目差异
  - 面试：红色强调。
  - AI：蓝色强调。

第一原则：模板统一结构，栏目只改变语义色和内容组件。

### Top-4：技术准确

- 内容来源
  - 凭记忆写稿：速度快但风险高。
  - 当日核验：优先官方文档、论文和权威源码。
- 表达结构
  - 只给标准答案：缺乏深度。
  - 原题、直觉、原理、追问、回答骨架、误区：完整建立技术可信度。

第一原则：每个技术结论必须能关联来源；不把有争议答案包装成唯一标准。

### Top-5：多平台适配

- 成片：三平台统一竖屏 9:16。
- 包装：小红书偏搜索与步骤；抖音偏冲突与短钩子；B站偏信息完整与知识摘要。

第一原则：内容核心唯一，平台标题、标签、描述分别适配。

## 3. 总体架构

```text
30天内容日历
  -> 每日 manifest
  -> 事实核验与脚本
  -> VoxCPM2 分段配音
  -> 音频时长测量
  -> Remotion 时间轴/字幕/动画
  -> 竖屏成片 + 统一封面
  -> 三平台文案
  -> 自动质量检查
  -> 19:00 Codex 审核包
```

### 模块边界

1. `planner`：从月度日历选择当日主题，处理日期锁与版本号。
2. `researcher`：保存来源和事实核验结果。
3. `scriptwriter`：输出配音稿、逐镜头 Markdown 与 JSON。
4. `voxcpm_adapter`：加载模型一次，分段生成并测量 WAV。
5. `remotion_renderer`：消费时间轴、音频和设计令牌，渲染视频与封面。
6. `platform_copy`：生成三平台标题、标签和描述。
7. `qa`：校验结构、时长、媒体属性、字幕安全区、来源和缺失文件。
8. `delivery`：在当前 Codex 线程提交审核包摘要与文件链接。

模块通过 `manifest.json` 与 `timeline.json` 交换数据，避免直接依赖彼此内部实现。

## 4. 双触发与每日时序

### 定时触发

- 17:00：创建日期目录、锁定选题、核验来源、生成脚本。
- 17:20：VoxCPM2 分段配音。
- 17:45：读取音频时长，生成动画、字幕和封面。
- 18:30：渲染并执行质量检查。
- 18:50：仅重试失败阶段。
- 19:00：提交审核包；若仍失败，提交已完成产物与明确错误报告。

### 手动触发

- “生成今天的视频”或“调用AI科普视频Skill”：立即运行当日任务。
- 当天已有成功版本：返回现有版本，除非用户明确要求重做。
- “重做今天的视频”：在同一日期目录创建 `v2`、`v3`，保留历史版本。
- 手动任务成功后，17:00 定时任务检测日期锁并跳过重复生产。

## 8. 视觉系统

- 画幅：1080×1920，30fps，60–90秒。
- 主底色：米白 `#F4EFE4`。
- 正文：黑色 `#151515`。
- 面试强调：红色 `#E83F32`。
- AI强调：蓝色 `#265CFF`。
- 封面：栏目标签、三行强标题、收益句、EP编号。
- 字幕：手机安全区内，关键词用栏目语义色强调。
- 动画：排版、流程图、代码卡片、数据结构、几何过程动画。
- 片头：不超过1秒；前3秒必须进入技术问题。

## 9. VoxCPM2 集成

使用 `D:\Project\VoxCPM2\VoxCPM` 的 `voxcpm` Python API。模型在一次生产任务中只加载一次。

默认策略：

- 使用 AI 设计音色，不默认克隆真人声音。
- 音色提示：清晰、中性、轻快、技术讲解感，停顿自然。
- 初始参数：`cfg_value=2.0`、`inference_timesteps=10`。
- 按场景分段生成，失败仅重试该段。
- 读取真实采样率与时长，合并为 `narration.wav`。
- 用户未来提供已授权参考音频后，才启用 `reference_wav_path`、`prompt_wav_path` 和精确转录。
- 审核包与平台描述标注 AI 配音。

## 10. 平台适配

### 小红书

- 搜索意图明确的标题。
- 描述采用问题、步骤、结论、收藏提示结构。
- 5–8个精准标签，避免无关热词堆砌。

### 抖音

- 短标题与强冲突钩子。
- 描述优先给结论和互动问题。
- 3–5个高相关标签。

### B站

- 信息完整、技术关键词清晰的标题。
- 描述包含知识点摘要、适用人群和 AI 配音声明。
- 5–7个分区相关标签。

## 11. 错误处理与恢复

- 每阶段更新 `manifest.json` 状态和时间戳。
- 已完成文件通过内容哈希与结构检查后跳过。
- 配音失败：只重试失败段，最多两次。
- 渲染失败：保留音频与时间轴，仅重新渲染。
- 质量检查失败：根据失败项回退到最近阶段。
- 同一问题连续三次失败：停止循环，发送现有材料、日志和最小人工决策请求。
- 19:00仍未成功：不得静默；发送失败报告和已完成产物。
